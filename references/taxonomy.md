# 踏雪风格体系分类（Taxonomy · 对外介绍版）

> 用途：对外介绍、README、分享、评审时的体系总览与分类口径。内部路由与执行规则以 SKILL.md 为准，本文件只回答「这个体系是什么、怎么分、为什么这样分」。
> 设计原则：**编号资产不动**（9 家族 61 变体的代号是稳定接口，已与台账、记忆、子技能、外部样图绑定）；科学性由「表现族归类 + 五变量语法 + 轴标签」三层承担，而不是靠重新划分目录。

## 一、一句话定位

踏雪风格引擎 = 一套风格化影像创作系统：**9 家族 61 变体的已固化模板资产**，按 **4 大表现族**归类，用 **五变量风格语法**组合，靠 **台账与自动检查器**治理，经 **子技能生态**扩展。

## 二、五层体系（系统架构）

| 层 | 名称 | 内容 | 对外一句话 |
|---|------|------|-----------|
| ① | 资产层 Style Library | 9 家族 × 61 变体；每变体 = 模板 + 量化规格 + 槽位 + 台账档案 | 「61 张已固化的风格底牌」 |
| ② | 组合层 Composition | 参考模板：母题系统（beast-myth）/ 单件范式（geometric-monument）/ 技法包（embroidery-illustration）/ 批量架构（brand-manual-visual）/ 用户专属模板；不占变体号，与任一资产组合 | 「风格之外的一切：母题、技法、批量架构」 |
| ③ | 方法层 Method | 三条管线（风格出图 / 提示词优化 / 元提示词创作）+ 出图路由 + 封装、矛盾扫描与质量自检规范 | 「三条可复用的创作流水线，每道交付都过闸」 |
| ④ | 治理层 Governance | verification-ledger 单一真源 + 用户偏好记忆 + 两个自动检查器（一致性核对 / 矛盾扫描回归） | 「每个模板都有台账档案与证据链，漂移会被脚本抓出来」 |
| ⑤ | 生态层 Ecosystem | 子技能路由：IP 插画 / 民国漫画 / 中译中 / 万象系列 / 图片反推 / 视频运动 / 艺术家门类 | 「大主题有专门的工作台，主库管风格」 |

## 三、资产层分类：4 大表现族 × 9 家族 × 61 变体

**划分依据 = 画面「用什么语言生成」**（笔绘 / 设计 / 镜头 / 空间）。这是对外第一问「你们有哪些风格」的回答骨架；表现族是归类视角，家族仍是路由与资产的基本单位。

| 表现族 | 家族 | 变体数 | 归类理由 |
|-------|------|-------|---------|
| **笔绘绘画族**（画出来的） | F1 笔意水墨 / F4 治愈插画 / F5 东方古典 | 14+5+13 = **32** | 以手绘笔触与工艺绘画为本体：水墨、绘本线描、剪纸、刺绣、绢本、月份牌 |
| **平面设计族**（设计出来的） | F2 留白海报 / F6 氛围实验 / F8 概念海报 | 11+2+1 = **14** | 以平面设计语法为本体：文字即设计、概念优先、留白构图、丝网印刷质感 |
| **摄影影像族**（镜头拍的） | F7 写实摄影 | **7** | 以镜头语言为本体：纪实、胶片、CCD、影棚、微距 |
| **微缩立体族**（空间搭的） | F3 城市建筑 | **3** | 以立体空间叙事为本体：纸雕、层叠景深、等距微缩模型 |
| **照片转换通道**（任务方向，非第五族） | F9 照片转艺术 | **5** | 由输入类型定义的任务型家族：照片输入，五种输出风格，美学可落任一表现族 |

合计 **61**。计数核对：32+14+7+3+5 = 61（与 verification-ledger 一致）。

## 四、五变量风格语法（科学内核）

**风格 = 媒介 × 构图 × 色板 × 情绪 × 工艺约束**（五变量独立可换，源自风格组合矩阵的第一性原理）。体系里的一切都是这个语法空间上的东西：

- 资产层的 61 个变体 = 五变量的 **61 个已采样组合点**（逐点固化模板；内部状态分级属治理信息，对外口径见 §六）
- 组合层的参考模板 = 变量替换的**安全模式**（母题替换、技法注入、批量架构，不新增代号）
- 组合矩阵 A/B/C/D 四级 = 组合空间的**分级边界**（A 已固化组合 / B 高潜力 / C 探索 / D 禁止）

对外表达：这不是 61 个孤立滤镜，而是一套语法下 61 个已固化的「词」，可以按语法组「句」——组句规则（内核+外壳、四层职责、A-D 风险分级）同样是资产。

## 六、对外介绍口径

**30 秒版**：踏雪是一个风格化影像创作引擎。底层是 61 个已固化的风格模板，横跨笔绘、平面设计、摄影、微缩立体四大表现族；中间是一套五变量风格语法，把模板当词、按语法组句；外面套三条创作流水线——风格出图、提示词优化、元提示词创作——每次交付都过矛盾扫描与质量自检；每个模板都有台账档案与证据链，两套自动检查器守护体系一致性。

**一页版结构**：五层体系图（§二）→ 4 表现族 × 61 变体总表（§三）→ 五变量语法示意（§四）→ 治理机制（台账+检查器）。

**措辞纪律**：
- 对外统一称「**已固化模板**」（模板固化、来源经多平台出图或实际使用验证），不展开内部状态分级、不枚举数量
- 「已验证」是内部台账（verification-ledger）的状态词，只用于体系内治理与三处同步，不进入对外话术
- 🔶 测试中 / ⚠️ 实验变体不进对外介绍

## 七、与内部路由的关系

内部执行仍走 SKILL.md 的既有链路：模式判断 → 子技能路由 → 主题默认映射 → 家族速查 → 变体索引。本文件的「表现族」是**归类视角，不是路由层级**——找风格按家族找，讲体系按表现族讲。今后新增家族时：先按「画面用什么语言生成」归入表现族（或增设第五族并在本文件登记），再走变体新增的三处同步流程。
