# 变体验证台账（单一真源）

> 用途：47 个变体的验证状态、证据、下一步集中在这里。SKILL.md §1 速查表与各家族文件的「状态」列必须与本台账一致；任何验证结果按 memory-protocol.md「验证状态回填」三处同步（家族文件索引+正文状态行、SKILL §1 速查表、本台账）。

## 状态定义

| 状态 | 含义 | 路由权限 |
|------|------|---------|
| ✅ 已验证 | 本体系内出图通过（Grok / Codex / 用户回传确认） | 可默认，可对外称已验证 |
| 默认 | 模板已固化且来源已验证（外部发布、多平台出图、用户提供、早期迭代固化） | 可默认路由，无需附加验证声明；不得对外自称已验证 |
| 🔶 测试中 | 效果不稳定或正在被用户测试 | 点名才用 |
| ⚠️ 实验 | 实验模板 | 点名才用 |

## 状态语义（2026-08-15 审计，同日按用户裁定修订）

「默认」= 源头已验证：模板来自已发布使用、外部多平台出图、用户直接提供或早期多轮迭代固化，质量证据在源头，可默认路由，不因未在本体系出图而受限。「✅ 已验证」仅表示本体系内出图通过，用于对外宣称与状态升级，不是进入默认路由的门槛。两者是证据来源之分，不是质量有无之分。
P1-P3 不是质量欠账，是顺手升级路径：有生图工具的会话出图通过即升 ✅。

## 验证优先级

- **P1（优先出图验证）**：F4-K、F7-H、F9-R1、F9-R4、F1-AF——用户最近开发/矩阵 A 级，主题高频。

## 维护规则

1. 出图验证后 24 小时内回填：本台账 + 家族文件 + SKILL §1，三处缺一即未完成。
2. 「✅ 已验证」只允许在体系内出图通过后使用；外部平台证据只能支持「默认」。
3. 效果不稳定 → 🔶 测试中；验证通过前不得提升为 ✅。
4. 新增/删除变体时先更新本台账，再更新 SKILL §1 与家族文件，最后更新 References 表计数。
5. 每次变更后运行 `python3 scripts/consistency-check.py`，输出 OK（9 家族 / 47 变体四处一致）才算同步完成。
