# 模式四：学习记忆

**存储位置**：
- `memory/user-preferences.md`：偏好档案（默认家族、默认比例、正/负反馈清单），只记偏好不记出图原文。
- 版本归档：默认写入 `memory/archive/YYYY-MM.md`（按月一文件，不存在则新建）；每次交付必写。用户在会话中指定其他归档路径时以用户指定为准；两处都不可得时，在交付说明中写明「归档未落盘 + 原因」，禁止静默跳过。归档含完整提示词，若本 skill 目录被发布或同步到公开仓库，`memory/archive/` 必须整体排除。

**双写铁律（本 skill 记忆闭环的强制规则）**：每次交付后，两条写入必须同时完成，缺一即交付不完整：
1. 在归档文件追加版本记录（格式见下；默认 `memory/archive/YYYY-MM.md`，用户指定路径时从其指定）
2. 在 `user-preferences.md` 更新偏好字段（默认家族 / 默认比例 / 正负反馈清单），并在该文件「使用历史」现有表格末尾追加一行（字段 = 日期 / 变体 / 主题类型 / 比例 / 用户反馈；**追加到已有表格，不要新建表格、不要放示例行**）。

**降级记录（无生图工具时也必记）**：本会话无 `image_gen` 且 Codex CLI 缺 `OPENAI_API_KEY` 时，出图验证无法执行 → 交付提示词时**必须同时交付一条「验证待办」**：请用户出图后回传结果，并明确问「这版保留率/风格是否达标」。用户回传后立即追加一行到使用历史，作为下次优化的校准依据。**禁止无验证、无记录的静默交付**——没有反馈记录的模式二输出视为未完成。

**验证状态回填（出图验证后必做，三处同步，缺一即未完成）**：验证通过 → ✅ 已验证；效果不稳定 → 🔶 测试中或 ⚠️ 实验。同步位置：① 家族文件变体索引状态列与正文「状态」行 ② 主 SKILL.md §1 速查表状态列 ③ `references/verification-ledger.md`（单一真源）。三处不一致的「已验证」不得对外宣称。

**显式更新触发词**：「记住」「以后都」「更喜欢 X」「不喜欢 X」「还是 X 风格好」。

**手改 diff 学习（最高优先级反馈信号）**：用户对交付提示词做手工修改时，diff 就是最直接的偏好表达，比出图后口头反馈更即时。每次发现用户手改，立即分析改了什么方向（例：「细微位移、疏密交错」→「轴向偏移与密度堆叠」= 偏好机制性描述而非效果性描述），把方向性结论追加到负反馈/正反馈清单，并说明「来自手改 diff」。下次优化同类提示词直接复用该偏好。

**版本归档（每次交付必写，不只是学习机制）**：每次提示词交付（优化或创作），在本地归档文件追加一条版本记录（路径由用户本地维护，不随 skill 分发），作为可学习、可归档、可复盘的资产库。记录格式：
```
## [主题] 版本 [Vn]（[日期]）
- 来源：[用户原始提示词 / 优化 / 创作]
- 原比例：[如 4:3] → 建议比例：[如 2:3] + 理由
- 七维诊断：[主体 5 / 风格 5 / 构图 4 / 光影 N/A / 色彩 5 / 质感 5 / 负向 4]
- 交付版本：[完整提示词]
- 变更说明：[逐条]
- 用户反馈 / 手改 diff：[待补 / 记录]
- 复盘结论：[这版哪些有效、下次同类提示词保留什么]
```
归档不是形式：每次交付前查一次档案，同主题/同风格历史版本直接参考；归档让提示词从「一次性输出」变成「可迭代资产」。

**偏好字段**：默认家族、默认比例、常用主题→变体映射、正/负反馈清单（负反馈原因必写，下次路由时规避）。

**路由应用**：
1. 用户说「踏雪风格」未指定变体 → 用记忆里的默认家族，无记录才回落 F1-A
2. 用户主题与历史主题同类型 → 优先复用历史变体
3. 负反馈清单里的变体组合 → 不再主动推荐，除非用户点名

**学习边界**：不记录出图的具体内容与人物细节，只记变体偏好与比例偏好，避免隐私沉淀。

**复盘方法（归档后必做）**：
1. 每次交付后，下轮交付前，查本地归档同主题/同风格历史版本
2. 对比相邻版本 diff，提炼「哪类描述被用户保留、哪类被删改」
3. 方向性结论（如机制性 > 效果性）写入正/负反馈清单，并标注「来自手改 diff」或「来自出图反馈」
4. 被验证有效的锁定句（如「线条是纯装饰性图形元素」）并入 optimize-pipeline.md 修复块表，形成资产复用闭环
